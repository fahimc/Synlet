Build this first

A small TypeScript harness manages the task lifecycle, context, permissions and model scheduling. llama.cpp serves generative GGUFs; a CPU worker serves Julia and embeddings. Ordinary tools perform exact calculation, file operations and verification.

Design choice

Do not claim this yet

This is not one trained neural network, a drop-in single GGUF, unlimited reliable context, or proven frontier-model quality. Bundling checkpoints creates one product interface—not a shared tokenizer, shared knowledge or automatically additive intelligence.

Scope boundary
Why selective? Research on scaling agent systems finds that coordination can help or hurt depending on the task. Our hypothesis is that complementary specialists plus verifiable tools will outperform indiscriminate agent debate on local workloads. [S24]

Evidence key: Source-checked means a specification or artifact was found in the linked source—not tested locally. Planning assumption means an unmeasured estimate. Acceptance target means a proposed release gate. All untagged architecture, budgets and policies are design recommendations.

Compaction and just-in-time retrieval are established context-engineering patterns. This implementation adds explicit provenance, versioning and measurable retention gates. [S17]

1. Originals

Store content outside model memory. Keep revision, source range, project, actor and trust level. Respect retention and deletion; originals are recoverable until the user’s policy deletes them.

2. Searchable chunks

Start with 400–800-token prose chunks. Prefer functions for code, sections for documents, and related events for logs. Include neighbourhood pointers and a separate exact-identifier index.

3. Working state

Keep goal, constraints, decisions, completed work, failed attempts, unresolved issues and next action. Separate user requirements from model proposals and tool observations.

The lookup algorithm

Filter by project permissions and source version first. Union the top 20 keyword and top 20 semantic candidates; combine ranks with reciprocal-rank fusion; deduplicate; pack up to 8 relevant chunks within the token ceiling. These counts are tunable starting values. FTS5 provides keyword ranking; embeddings require a separate vector-search component. [S18] [S12]

For v0.1, use a per-project, memory-mapped vector matrix and cosine search for a bounded corpus; benchmark query latency as it grows. Move to an approximate nearest-neighbour index when measured search latency exceeds the budget. Never describe storage capacity as unlimited reliable model context.

Compaction trigger

Before each model call, count the rendered prompt with that model’s tokenizer. Above 75% of its input allowance, first remove duplicates, then compact completed work towards 55%. Keep complete tool-call/result pairs. A 3K prompt needs no artificial compression just to reach a ratio.

Qwen drafts notes; host checks IDs and preserved exact fields. On failed checks, keep original excerpts or escalate to the controller. Do not recursively summarise summaries as the only record.

Information that must survive

Current instructions and explicit corrections; numbers and units; paths and identifiers; negations; unresolved failures; proof of what actually ran. Preserve critical constraints verbatim, and never let a summary become more authoritative than its source.

The vision record links to the original image and coordinates. Text embeddings index its observations—not the raw image itself.

05Execution design

A small, explicit harness—not a stack of chatbots.

Proposed foundation: Node.js/TypeScript + Fastify, a durable SQLite task machine, llama.cpp inference adapters, and a pinned Python CPU worker. No Docker is required for this design.

What we reuse

Fastify for API schema validation; llama-server for model loading and generation; SQLite FTS5 for records and keyword retrieval; Playwright for an owned, visible browser; Python for Julia, embeddings and numerical tools. [S19] [S14] [S18] [S20]

06Worked example

“Read this error, fix the code, then test it.”

A concrete sequence shows how the models cooperate without passing a huge transcript around. The figures below are illustrative context sizes, not measurements.

Route the request · about 0.5–1K input

An attachment makes vision relevant. Julia also identifies code/tool needs. The host records the requested scope; no write permission is inferred from a probability score.

Observe the screenshot · one bounded image + task

LFM-VL extracts the error, visible file references and uncertainty. The original screenshot and coordinates remain available. Unclear text is rechecked rather than guessed.

Retrieve the relevant files · about 3–6K input

The context engine looks up matching errors and symbols. K2 reads exact current source, relevant tests and pinned constraints—not the whole repository.

Propose and execute a focused patch

The host checks the expected file revision and workspace boundary. After required approval, it applies the patch and runs a bounded test command in an isolated test environment.

Verify; repair at most twice

Tests, type checks and observed application behaviour determine the outcome. Failed tests return a compact diagnostic packet. A timed-out or truncated model response is not success.

Commit a checkpoint and answer

The controller reports what changed, what passed and what remains unchecked. The compactor records the outcome with source IDs; code and full logs stay retrievable.

No maths expert is needed here. Conversely, a calculation-only task should not load the code or vision model. The quality of routing includes knowing what to leave out.

10Trust, permissions & resilience

Bound the autonomy outside the models.

Routing scores can suggest a workflow. They must never grant access to a directory, unlock a browser session or approve a consequential action.

Protect execution

Use an allowlisted tool catalogue and workspace roots, expected-revision patching, explicit shell permission, timeouts, output caps and a dedicated low-privilege account. Require confirmation for deleting outside a sandbox, publishing, sending messages, purchases and privileged installations.

Native processes are not a security sandbox. Untrusted code/tests need a disposable VM or similarly strong isolation. Browser contexts isolate sessions, not the host filesystem. Never execute extracted document instructions as commands.

Recover without repeating harm

Persist the intended action before execution, then its receipt and observed result. Retry read-only calls automatically within limits. For writes, reconcile actual state using an idempotency key or provider receipt; never blindly replay after a crash.

Use loop signatures, a 12-model-step initial cap and at most two repair retries. If the budget is exhausted, save a checkpoint and explain the blocked state. Longer work requires a deliberate budget change.

Keep data correctly scoped

Project permissions apply before retrieval. Store secrets separately, redact them from telemetry, and encrypt sensitive local storage using host facilities. Give users a deletion path covering originals, chunks, vectors, summaries and backup retention.

Version facts and indexes. Changing embedding weights, dimensions or text normalisation triggers a controlled reindex, not mixing incompatible vectors.

Handle bad evidence honestly

Treat web pages, skill imports and tool output as untrusted data. Preserve their origin through compaction. Reject source IDs that do not exist; flag uncertain OCR and conflicting facts. Display offline freshness and incomplete document coverage.

No silent cloud fallback. When a model cannot solve the task within limits, return the evidence and remaining uncertainty or use an explicitly enabled escalation policy.

ACOMPATIBILITY

Pin the environment and prove every selected artifact can run.

Build the model manifest; record hashes, licences, driver and runtime. Test prompt templates, Q4 outputs, model loading, vision projectors, tool parsing and cancellation. Benchmark the hardware rather than copying someone else’s throughput.

Exit: a per-role compatibility report. Disable or replace any failing checkpoint; MiniCPM is the initial text fallback.
BUSEFUL BASELINE

Ship one controller with safe tools and durable state.

Implement the gateway, bounded state machine, approval flow, workspace patching, calculation and a small visible-browser toolset. Add Julia routing with an uncertainty fallback to the controller.

Exit: baseline tool suite passes; crash recovery does not duplicate side effects; measured latency recorded.
CCONTEXT ENGINE

Make long histories retrievable without losing their meaning.

Add ingestion, source revisions, FTS5, embeddings, lookup tools, pinned constraints and Qwen compaction. Include exhaustive-scan mode and source/summary invalidation.

Exit: retrieval and fidelity gates pass; repeat the same end-to-end tests with and without compression.
DSPECIALISTS

Add vision, maths and code one at a time.

Implement bounded handoffs, role-specific contexts and result schemas. Compare MiniCPM alone with each specialist and the full sequence at matched budgets.

Exit: retain only experts that add measurable task success or latency benefit without unacceptable regressions.
EPACKAGE & LEARN

Create the portable bundle, then investigate training.

Add local setup, health checks, clean shutdown, version rollback and a single API identity. Collect consented, verified task traces. Evaluate router fine-tuning, compatible adapters and distillation as separate experiments.

Exit: clean-machine install and release evaluation pass. Do not claim a single-GGUF model unless a supported integrated architecture is actually produced.
The product is the smallest workflow that reaches a defensible answer.

Not the number of models loaded. Not the advertised context limit. Not the length of the reasoning trace.

SQLite is the local adapter—not a distributed database. WAL permits readers alongside a writer, but there is only one writer at a time and its shared-memory mechanism is not suitable for a network filesystem. Keep transactions short and the database on the host’s local disk.[S34]

Expected errors, not ambiguous strings

Use stable codes such as POLICY_DENIED, CONTEXT_LIMIT, STALE_REVISION, RESOURCE_EXHAUSTED, CAPABILITY_UNAVAILABLE and OUTCOME_UNKNOWN. Include a safe message, correlation ID and host-defined retry category.

At-least-once work; controlled side effects

A queue may redeliver after a crash. Use compare-and-set task revisions, leases and fencing tokens to reject stale completions. Repeated read-only work is acceptable within a budget.

A side effect with an uncertain outcome must be reconciled against a provider receipt or observed state. No idempotency key can force an uncooperative external service to execute exactly once.

Separate trusted and untrusted processes. Julia/embedding inference runs in the trusted model worker. Generated code, repository tests and shell tools run elsewhere under restricted execution policy. For adversarial code, use actual OS/VM isolation—not a timeout labelled as a sandbox.

To add storage: implement the same repository/transaction ports and run the common conformance suite. Do not copy the whole application into a new fork for each provider.

A model can change. The system’s rules should not.

The maintainability test is whether a replacement, bug fix or new capability stays within a small, explicit boundary—with evidence that the rest of the assistant still behaves correctly.
