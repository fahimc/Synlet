- That failed bootstrap left one stale project-registry reparse entry in the local
  pnpm cache. Removal attempts returned Windows error 649. It contains no project
  data, but a future pnpm store repair/prune may be needed on this host.
- The hosted Linux CI lane is configured but SKIPPED locally: publishing/pushing was
  not authorised, and the available WSL distribution is Docker Desktop internals,
  not a supported validation host.
- GPU, model smoke, integration, security and end-to-end suites belong to later cards.
  Their commands fail explicitly until those cards implement them.

## Security, migration and compatibility impact

The gateway binds only to `127.0.0.1`, caps request bodies at 64 KiB, performs no
network/model calls and exposes no tools. Runtime profiles reject extra properties at
every level. There is no persisted state or migration in T00.

Node 24.21.0 is the locked CI baseline. Node 26.8.2 was also observed during bootstrap,
but it is not the release baseline. On exFAT checkouts, pnpm's store registry may need
to reside on a symlink-capable NTFS volume; normal NTFS and Linux CI use the standard
frozen install command.
